# クラウドワークス:案件の判定と提案文の下書き

ユーザーの代わりに「この案件を Claude が作業して納品できるか」を判定し、できるものだけ提案文を書く。
**応募そのものはユーザーが手で行う。** クラウドワークスにログイン・自動投稿・スクレイピングをしない。

## 手順

1. `crowdworks/profile.md` を読む。
2. 貼られたテキストを案件ごとに分ける(「---」区切り、または案件タイトルの切れ目)。
3. 案件ごとに `python3 crowdworks/cw.py new "<案件タイトル>" --url "<URLがあれば>"` を実行し、本文は標準入力で渡す(heredoc)。作られた `crowdworks/jobs/<id>/job.md` の「判定」欄を埋める。
4. 判定を下の基準で決め、`python3 crowdworks/cw.py status <id> screened --verdict <GO|保留|見送り>` を実行。
5. GO の案件だけ `crowdworks/jobs/<id>/proposal.md` を書き、`status <id> proposed` にする。
6. 最後にユーザーへ、表で一覧(ID / タイトル / 判定 / 一言理由 / 報酬 / ユーザーの拘束時間)と、提案文ファイルへのパスを返す。提案文の全文はチャットに貼らない(ファイルを見てもらう)。

## 判定基準

### 見送り(1つでも当たれば)
- 発注者が AI 使用を禁止・制限している(「AI不可」「ChatGPT等の使用禁止」「AIチェックあり」など)
- 電話・ビデオ会議・対面・常駐・顔出しが必須
- ユーザー本人の体験が要る:体験談、口コミ、レビュー・アンケート回答、SNS投稿、アプリ利用報告
- ステマ・やらせ・なりすまし、アカウント作成代行、いいね・フォロー・レビュー稼ぎ、他人名義での投稿
- 資格・免許が要る(税務・法律判断、医療助言など)
- 外部連絡先(LINE・メール・別サイト)への誘導、仮払い前の作業要求、個人情報の提出要求 → 規約違反・詐欺の典型
- 情報商材・副業塾・MLM の勧誘、「誰でも簡単に高収入」
- 実在の素材(写真撮影・現地取材・実機検証)が要り、ユーザーも用意できない
- 下の「Claude の対応範囲」の外にある

### 保留(ユーザーに判断してもらう)
- 内容は Claude で作れるが、要件があいまい、または規模が読めない(発注者への質問案を job.md に書く)
- 継続案件で、初回だけ見て判断しにくい
- 専門性が高く品質を担保できるか不安
- 対応範囲の境目にある(例:動画で「おしゃれに」「YouTuber風に」と雰囲気の指定が強い)

### GO
- 成果物がファイル(文章・コード・表・HTML・画像・動画 等)で完結し、Claude がこの環境で作って検証できる
- 必要な追加情報があっても、質問すれば埋まる範囲
- 単価の安さは理由にしない(最低ラインなし)

## Claude の対応範囲(本人の技能は前提にしない)

この環境で使える道具:Python、ffmpeg/ffprobe、ImageMagick、LibreOffice、ブラウザ(Playwright/Chromium)、docx/xlsx/pptx/pdf スキル。

| 分野 | GO | 見送り |
|---|---|---|
| 動画編集 | カット・結合、無音部分の削除、字幕(原稿・文字起こしがある/作れるもの)、テロップの焼き込み、リサイズ・縦横変換・圧縮、BGM・効果音の差し込み、ショート切り出し、サムネ画像 | 凝ったモーショングラフィックス、アニメーション制作、手描き風演出、After Effects/Premiere のプロジェクトファイル納品、音声の聞き取りが要るのに文字起こし手段が無いもの |
| デザイン | バナー、SNS画像、サムネイル、スライド・資料、チラシ・名刺などのレイアウト(HTML/SVG で作って画像・PDF に書き出す)、Canva 風の文字中心デザイン | ロゴの独自性が問われるコンペ、イラスト・キャラクター制作、写真の高度な加工・合成、Photoshop/Illustrator 形式での納品必須 |
| ホームページ | 静的サイト・LP、HTML/CSS 修正、WordPress のテーマ・記事の調整(ファイル渡しで済むもの) | 本人がサーバーや管理画面に入って作業し続ける必要がある常駐・運用 |
| 業務の自動化 | Excel 関数・マクロ・GAS・Python、CSV 加工、スクレイピング以外の自動化 | 規約違反になり得るスクレイピング・自動投稿・ボット作成 |
| データ入力 | 渡された資料(PDF・画像・表)からの転記・整理・集計 | 発注者の管理画面に本人がログインして延々入力する形式(拘束時間が報酬に見合うかを書いて保留) |
| 文章・翻訳 | 記事、商品説明、マニュアル、日英翻訳 | 本人の体験・取材が要るもの、専門資格が要る内容 |

### 拘束時間の出し方
報酬(手取り:システム利用料を引いた額)と並べて、**ユーザーが手を動かす時間**(応募・確認・やりとりの中継・納品)を書く。最低ラインはないので判定には使わず、ユーザーが優先順位を決める材料にする。
システム利用料の率は案件ページや規約で変わり得るので、分からなければ 20% で仮置きし、仮置きと明記する。

## 提案文の書き方(proposal.md)

```
# 提案文:<案件タイトル>

<!-- 提示金額: ○○円 / 納期: ○日 / 根拠: … -->

(本文)
```

- 冒頭で、発注者の依頼内容を自分の言葉で一文で言い直す(読んだことが伝わる)。
- 進め方を具体的に(何を、どの順で、いつ出すか)。初回提出の時期を書く。
- 経歴は profile.md に書かれた事実だけ。実績の水増し・架空の実績・存在しないポートフォリオは書かない。
- AI 利用の一文は入れない(profile.md の設定)。「AIは使いません」とも書かない。
- 製造業に関係する案件でだけ、現場経験を一言添える。
- 質問があれば最後に1〜2個だけ。
- テンプレの使い回し感を出さない(案件ごとに中身を変える)。300〜500字。
- 金額・納期の根拠はコメントに書き、本文には結論だけ。
