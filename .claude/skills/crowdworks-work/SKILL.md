# クラウドワークス:受注案件の実作業と納品準備

成果物を作るのは Claude。**納品・メッセージ送信はユーザーが手で行う。** クラウドワークス上の操作はしない。

## 手順

1. 案件を特定する。ID が無ければ `python3 crowdworks/cw.py list` から選ぶ(候補が複数ならユーザーに聞く)。
2. `crowdworks/jobs/<id>/job.md`(原文・判定)と `proposal.md`(約束した内容)、`crowdworks/profile.md` を読む。ユーザーが貼った追加メッセージ・資料は job.md の「やりとりメモ」に日付つきで追記する。
3. `status <id> working` にする。
4. **要件を箇条書きに分解**し、`crowdworks/jobs/<id>/delivery.md` の「要件チェック表」に先に書く(文字数、形式、ファイル名、トーン、禁止事項、納期、提案で自分が約束したこと)。
   - 要件があいまいで、間違えると作り直しになる箇所は、作業を止めて発注者への質問文を作り、ユーザーに渡す。推測で進める場合は、推測した内容をチェック表に書く。
5. 成果物を `crowdworks/jobs/<id>/deliverables/` に作る。
   - 文章:指定形式(指定が無ければ .docx が求められそうなら docx スキル、それ以外は .md / .txt)。文字数は実測する。
   - コード・HTML:実際に動かして確認する(テスト、ブラウザでの表示確認、スクリーンショット)。
   - 表計算:xlsx スキルを使い、数式が壊れていないか確認する。
   - 事実を書く原稿は、確認できない数値・固有名詞を作らない。出典が要る主張には出典をつけるか、ユーザー確認が要る箇所として印をつける。
   - 他者の著作物の丸写し・リライトによる盗用はしない。
6. 自己チェック:チェック表の各行を ✅ / ⚠️(要ユーザー確認)/ ❌ で埋め、根拠(文字数の実測値、動作確認の結果など)を書く。❌ が残るなら直してから進む。
7. `delivery.md` の後半に「納品メッセージ案」を書く(成果物の一覧、確認してほしい点、修正対応の案内。短く)。
8. `status <id> review` にし、ユーザーへ:成果物のパス、⚠️ の箇所、ユーザーが目で確認すべき点を短く返す。

## delivery.md の形

```
# 納品準備:<案件タイトル>

## 要件チェック表
| # | 要件 | 出典(原文/提案/メッセージ) | 結果 | 根拠 |
|---|---|---|---|---|

## 成果物
- deliverables/…

## あなたに確認してほしいこと
- 

## 納品メッセージ案
```

## 修正依頼・やりとり

- 発注者のメッセージが貼られたら、やりとりメモに追記し、返信案をチャットに出す(短いので直接貼ってよい)。
- 修正依頼は、チェック表に行を足してから直す。旧版は `deliverables/old/` に残す。
- 追加作業が当初の範囲を超えるなら、追加料金・納期の相談文案を出す。無償で広げない。
- 発注者が外部連絡先・直接取引・評価の操作を持ちかけてきたら、応じない返信案を出し、ユーザーに注意を促す。
